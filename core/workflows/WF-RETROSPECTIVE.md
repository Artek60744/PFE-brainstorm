# WF-RETROSPECTIVE

## Objectif
Analyser une phase, un sprint ou un projet passé pour extraire les leçons apprises. Produire :
- Une liste des succès à reproduire
- Une liste des échecs à éviter
- Des actions d'amélioration concrètes
- Une mise à jour des processus si nécessaire

---

## Agents impliqués
- **MANAGER-DEBAT** (orchestrateur)
- **AGENT-PRODUIT** (perspective valeur, satisfaction utilisateur)
- **AGENT-ARCHITECTE** (perspective technique)
- **AGENT-DEVOPS** (perspective opérationnelle)
- **AGENT-CRITIQUE** (identification des angles morts)

---

## Étapes

### 1. [MANAGER-DEBAT] Cadrage
- Définit le périmètre de la rétrospective (phase, sprint, projet)
- Rappelle les objectifs initiaux et les KPIs définis
- Présente les faits : livrables réalisés, délais respectés ou non, incidents
- Pose le cadre bienveillant : analyser pour améliorer, pas pour blâmer

### 2. [CHAQUE AGENT] Collecte individuelle
Chaque agent répond à 4 questions :

**Ce qui a bien fonctionné (Keep)**
- Pratiques à conserver
- Décisions qui ont payé

**Ce qui a mal fonctionné (Stop)**
- Pratiques à abandonner
- Décisions regrettées

**Ce qui a manqué (Start)**
- Pratiques à introduire
- Outils ou processus manquants

**Ce qui était confus (Clarify)**
- Zones d'ambiguïté
- Responsabilités floues

### 3. [MANAGER-DEBAT] Consolidation
- Regroupe les retours par thème
- Identifie les points de convergence (plusieurs agents mentionnent le même point)
- Identifie les divergences (un agent voit un succès, un autre un échec)

### 4. [AGENT-CRITIQUE] Analyse approfondie
- Challenge les succès perçus : était-ce vraiment un succès ou de la chance ?
- Challenge les échecs perçus : était-ce vraiment évitable ?
- Identifie les causes racines (pas juste les symptômes)
- Propose des actions de fond (pas juste des pansements)

### 5. [DÉBAT] Discussion ouverte
- Les agents débattent des divergences
- Le CRITIQUE challenge les justifications
- Objectif : converger vers une compréhension partagée

### 6. [MANAGER-DEBAT] Plan d'action
- Priorise les actions d'amélioration (max 3-5 actions concrètes)
- Assigne un responsable et une échéance à chaque action
- Documente les décisions pour référence future
- Met à jour les processus/workflows si nécessaire

---

## Livrables attendus

| Livrable | Format | Responsable |
|----------|--------|-------------|
| Synthèse Keep/Stop/Start/Clarify | Tableau consolidé | MANAGER |
| Analyse des causes racines | Liste argumentée | CRITIQUE |
| Plan d'action | Tableau (action, responsable, échéance) | MANAGER |
| Mise à jour des processus | Diff des documents modifiés | MANAGER |

---

## Conditions d'arrêt
- Maximum 3-5 actions d'amélioration (éviter la liste infinie)
- Chaque action doit être SMART (Spécifique, Mesurable, Atteignable, Réaliste, Temporelle)
- Les divergences non résolues sont documentées, pas ignorées

## Règles de bienveillance

1. **Pas de blâme personnel** : Critiquer les processus, pas les personnes
2. **Faits avant opinions** : Commencer par les données objectives
3. **Solutions avant plaintes** : Chaque problème doit avoir une proposition de solution
4. **Écoute active** : Laisser chaque agent s'exprimer complètement
5. **Divergences documentées** : Les désaccords sont notés, pas cachés
